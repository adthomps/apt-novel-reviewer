# Project Context

> Generated from `docs/apt/references/project-profile.json`. Do not edit this file directly; update the JSON profile and run `npm run inventory:generate`.

## Purpose

App for reviewing personal writing and providing feedback and direction.

APT Local Novel Review Desktop App (V1): a local-first, review-only Electron + React + TypeScript + Vite desktop app in a pnpm workspace that imports .docx manuscripts as versions, parses them into chapters, runs structured review modes through a local Ollama model (gpt-oss:20b), persists projects, versions, chapters, review runs, and findings in SQLite (better-sqlite3), and compares findings across versions (resolved, still, new). Shared types, lib (parsing, schemas, prompts, compare), db (migrations and repositories), and ui packages support the desktop app.

- Repository type: `monorepo`
- Maturity: `active`
- Owner: APT
- Profile maintainer: APT Novel Reviewer maintainers
- Primary audiences: authors, editors, manuscript reviewers, APT builders

## Architecture

The renderer requests actions through window.aptApi; the preload forwards them over IPC; the Electron main process validates input, handles filesystem, SQLite, and Ollama calls, and returns typed payloads. Calls are one-way renderer -> preload -> main.

- apps/desktop (@apt/desktop): Electron app with main (IPC handlers, runtime, review, versioning, and path services), a minimal preload API, and the React renderer pages (Setup, Library, import, review, findings, compare, settings, canon).
- packages/lib (@apt/lib): DOCX parsing into chapters, Zod schemas for review results, Ollama prompt and client logic, hashing, and version compare logic, with unit tests.
- packages/db (@apt/db): SQLite migrations (001_init, 002_review_run_summary) and repositories.
- packages/types (@apt/types): shared domain types.
- packages/ui (@apt/ui): reusable UI components and tokens for the dark-first, card-based APT styling.

- Runtime model: A Windows desktop Electron app. The main process talks to Ollama only at http://127.0.0.1:11434 and stores data in SQLite under %APPDATA%\@apt\desktop\apt-novel-reviewer (development uses a separate APT-Novel-Reviewer-Dev directory). contextIsolation is on, nodeIntegration is off, the renderer never calls Ollama directly, and CSP limits connections to the local Ollama endpoint.
- Deployment model: Not a Cloudflare app. pnpm release:win builds an unsigned Windows 10 22H2+ x64 NSIS installer and SHA-256 checksum in release/ (ignored) with electron-builder; nothing is published and there are no automatic updates. Releases must be accepted on a clean Windows account or VM before sharing.

## Build and Run

Install Node 22 LTS and pnpm 9.12.1, run pnpm install (better-sqlite3 needs native tooling on Windows), start the desktop app with pnpm dev, and validate with typecheck, lint, and test. Reviews need a local Ollama with gpt-oss:20b, which the Setup page can install, start, and download on request.

- Package manager: pnpm workspace (apps/desktop and packages/*); root scripts run recursively or filter @apt/desktop.
- Local server: None. pnpm dev runs electron-vite dev to open the desktop app.
- Build: pnpm build runs electron-vite build for the desktop app and declaration-only tsc builds for packages into ignored packages/*/dist.
- Deployment: pnpm release:win builds the Windows x64 installer and its .sha256 in release/; pnpm release:dir builds the unpacked app in release/win-unpacked. node scripts/smoke-release.mjs smoke-tests a packaged build.

### Integrations

- Ollama local API at http://127.0.0.1:11434 runs review modes with gpt-oss:20b; the app reuses a running Ollama and stops only a server it started.
- The Setup page links to the official Ollama Windows installer, locates ollama.exe, and pulls the model with per-layer progress only when the user asks.
- SQLite through better-sqlite3 stores projects, versions, chapters, review runs, and findings.
- electron-builder and NSIS produce the Windows installer; release builds download Electron and NSIS tools.
- GitHub Actions ci.yml validates the profile, typecheck, lint, and tests on Node 22 and pnpm 9.12.1; apt-check.yml runs the APT check.
- apt-principles-agents distributes reusable doctrine and agent assets; local workflow decisions stay here.

## Constraints

- This is a review tool, not a writing tool: do not add manuscript rewriting or editing features, and do not add chat assistant UI.
- Keep the architecture local-first: no cloud APIs, cloud services, or telemetry by default; the Ollama endpoint is local only and manuscripts are sent only there.
- Preserve the split between Electron main/preload and the React renderer; do not bypass the preload security boundary and keep calls one-way renderer -> preload -> main.
- Every import creates a new manuscript version.
- Review outputs must be strict, schema-validated JSON; validate external inputs and runtime contracts with Zod.
- Default model for V1 is gpt-oss:20b; SQLite is the structured persistence layer.
- Preserve manuscript and user content boundaries and do not invent review claims without source evidence.
- Keep reusable review doctrine upstream in apt-principles-agents; local workflow decisions stay here.
- UI follows APT: dark-first palette, card-based layouts, low visual noise, single accent focus, subtle motion only.
- New logic should include unit tests where practical; keep modules small and single-purpose and avoid hidden global state.
- Upgrades and uninstall must preserve project and manuscript data; uninstall does not remove Ollama or its models.
- The local release is unsigned and has no automatic updates or publishing; only install builds from a trusted source.
- Implementation order: app shell and runtime, project system, DOCX import and chapter parsing, SQLite persistence, Ollama review engine, findings and compare, remaining review modes and polish.
